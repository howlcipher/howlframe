# Action Executor

Sandboxed Action Executor — demonstrates a finite trusted action catalog where untrusted AI/user proposals can request operations but cannot select arbitrary code, paths, capabilities, or execution primitives.

## Architecture

This application receives a high-level intent (proposal) in JSON form, generated by an untrusted source (like an AI). It separates the untrusted *request* for an action from the trusted *execution* of that action.

1. **Authorization phase**: The proposal is mapped against a strict, finite catalog of allowed actions (e.g., `stage_artifact`, `write_release_marker`). Deterministic rules and state transitions (e.g., cannot deploy if not staged) are evaluated.
2. **Execution phase**: Only if a decision is `ALLOW` does the application execute a bounded, hardcoded local effect.

The untrusted proposal *never* provides an arbitrary filesystem path, shell command, or executable argument to the engine.

## Compilation and Standalone Execution

Since HowlFrame is an autonomous runtime with a dedicated VM, this application compiles to standalone bytecode, providing proof that intent evaluation doesn't rely on arbitrary backend Go code executing LLM text. 

The compilation path used by this application:
1. `.howl` source
2. lexer
3. parser
4. semantic checker
5. HFIR target verification
6. bytecode compiler
7. serialized `.hfbc`
8. executed on HowlFrame VM via `howlframe -run-bc`

## Running

```bash
# Compile to bytecode
howlframe -compile-bc action_executor.howl -o action_executor.hfbc

# Run
howlframe -run-bc action_executor.hfbc proposal.json [evidence...]
```
