# map_keys

## Why this slice

HowlBoard's dogfooding journal ranks the remaining Frame gaps by cost. The
largest is bytecode modules, which is a compiler redesign and was deliberately
left alone. The next gap is dict enumeration: `store_keys` lists store
records, but a dictionary received from `parse_json` or nested in a record
still has no key list. HowlBoard changed `/api/projects` to return
`[{name, count}]` instead of `{name: count}` because a HowlFrame client could
not iterate the object's keys.

That is the smallest platform primitive that makes record-shaped application
data usable on the bytecode runtime, without a new capability and without
touching Factory or Board.

## Contract

`(map_keys dict)` evaluates `dict` and pushes its keys as a list of strings,
sorted lexicographically. An empty dictionary is an empty list, not nil.
A non-dictionary fails closed with `TYPE_ERROR`. The operation is pure: it
does not require `database` or any other grant.

The same form lowers in the interpreter, the Go backend, and the JavaScript
backend. JavaScript sorts `Object.keys` so a browser client sees the same
order the VM does for ordinary keys.

## What this does not do

It does not add bytecode modules, chained `map_get`, query-string or path
parameters, or `html_escape`. Those remain separate gaps. `map_keys` does not
widen any capability.
