## Phase 3: Artifact Format Implementation
- Decided on binary format: `HFBC` magic + `uint32` version + `uint32` payload_length + 32-byte SHA256 + payload.
- Implemented `bytecode.WriteArtifact` and `bytecode.ReadArtifact` in `internal/bytecode/artifact.go`.
- Changed `howlframe.go` to use this layout.

## Phase 4: Malformed Bytecode Attacks
- Unit tests (`artifact_test.go`) explicitly cover corrupted magic bytes, mismatched versions, tampered SHA-256 hashes, and trailing garbage data.
- The `ReadArtifact` function successfully rejects all adversarial inputs before any decoding happens.

## Phase 5-7: Capability and Budgets Adversarial Passes
- Unit tests in `internal/vm/capability_test.go` and `internal/vm/limits_test.go` verify that capabilities are enforced independent of the compiler.

## Phase 8: Bug #42 HFIR_UNBOUND_REF Fix
- Discovered that the `HFIR_UNBOUND_REF` diagnostic in `verifier.go` was functionally dead code with zero reachable true positives, because genuinely unbound variables trigger an `os.Exit(1)` panic in the `checker` pass before HFIR is ever generated.
- Safely removed the diagnostic to fix the false positives, meaning legitimately dynamic variables (like inside `try_let`, `parse_json`, lambda params) no longer spuriously fail.
