# HowlFrame v0.4.0

## What it is
A minor release from `main`. It completes interactive terminal programs with a deterministic test mode, line editing, paste safety, colour and scrolling. It also adds a structured verification report, and the VM's lists become a persistent vector, so building a list by repeated appends no longer copies it each time.

HowlPlane's pure HowlFrame TUI (`howlplane tui`, HowlPlane ADR 0010) is the first consumer of the terminal features and was tested against this commit line.

## New
| | What | Where |
|---|---|---|
| `howlframe run --replay` | Drives a `terminal_app` from a recorded event file and writes one `howlframe.terminal_replay/v1` record per handled event. Effects are recorded, never executed, so a program's decisions can be tested with no terminal, grants or child processes (#118). | `docs/reference/terminal_app.md` |
| Line editing and history | Raw mode edits the line with a cursor: the arrow keys, Home, End and Delete, and the usual Ctrl keys. Up and Down recall up to 200 lines of this session's history, which is kept in memory only (#119). | `docs/reference/terminal_app.md` |
| Bracketed paste | A paste is inserted as text, with line breaks as spaces, and never sends the line by itself. Every `line` event carries `pasted`, so a program can refuse a pasted confirmation (#119). | `docs/reference/terminal_app.md` |
| Styles and `--color` | A view entry may be `{"text", "style"}`, with the style taken from a fixed palette. Only the runtime writes terminal codes, and the text is still sanitized. `--color auto\|always\|never` decides when styles are drawn; `auto` honours `NO_COLOR` and `TERM=dumb` (#119). | `docs/reference/terminal_app.md`, `docs/cli.md` |
| Scrolling | PageUp and PageDown scroll a view taller than the screen, with indicators for the hidden lines. A scrolled view keeps its place when a new frame arrives (#119). | `docs/reference/terminal_app.md` |
| Verification Report v0 | `howlframe check --json` and `howlframe inspect --report` emit one `howlframe.verification_report/v0` object: named checks, component versions, HFIR blocking codes and explicit limitations, with no timestamps or temporary paths. `agent check --json` attaches the same report. | `docs/cli.md`, `docs/reference/agent_interface.md` |

## Behavior changes
- **`line` events carry `pasted`.** The field is added to every `line` event, raw mode and line mode alike. It is always false in line mode. Handlers that read fields by name are unaffected.
- **Raw-mode keys.** Up and Down now recall history; before, they were ignored. Raw mode turns bracketed paste on, and every exit path turns it off.
- **Lists.** The VM and the interpreter keep lists in a persistent 16-way vector (#111). Appending no longer copies the whole list, and list values behave as before.
- **Legacy `-run-bc`.** It now validates the same execution limits as `howlframe run`, including `--max-processes`, `--max-exec-millis`, `--max-startup-instructions` and the `terminal_app` per-event limits.
- **`build --target wasmgc`** runs the HFIR gate, as the other targets do, so a program the gate blocks no longer builds for that target. The WebAssembly GC backend is still in development.
- **`check` and `inspect`** accept flags after the input file again.
- **Generators.** The Go and JavaScript generators keep their state per compilation, so compilations in one process no longer share state.

HowlPlane's consumer check of the list change found a regression in the `--replay` recorder before release: records lost views and effects built with list literals. It was fixed in #321, with a regression test.

## Compatibility
| | v0.3.0 | v0.4.0 |
|---|---|---|
| `howlframe version` | `HowlFrame 0.3.0`, `HFBC format: 2` | `HowlFrame 0.4.0`, `HFBC format: 2` |
| Artifacts | format 2 | format 2. v0.3.0 artifacts run on v0.4.0. |
| `terminal_app` events | | additive: `pasted` on `line` |
| Runner flags | | additive: `--replay`, `--color` |
| Grants | | unchanged |

`terminal_app` runs on the bytecode VM only. The interpreter, HFIR and the Go, JavaScript and WebAssembly targets do not support it.

## Installation
Archives are named `howlframe_v0.4.0_<os>_<arch>.tar.gz` (`.zip` for Windows). Verify them against `SHA256SUMS`; the steps are those of `docs/installation.md` with `VERSION=v0.4.0`. Platform execution status there was recorded for v0.2.0 and is not re-claimed here.
