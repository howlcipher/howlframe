# HowlFrame v0.3.0

## What it is
A minor release from `main`. It adds interactive terminal programs and the process bounds and grants they need. It also contains every fix in v0.2.1: the `spawn` and input resource bounds, bugs.md #73 to #76.

HowlPlane's pure HowlFrame TUI, `howlplane tui --engine howlframe` (HowlPlane ADR 0010), is the first consumer and was tested against this commit line.

## New
| | What | Where |
|---|---|---|
| `terminal_app` | Interactive terminal programs. The runtime owns the terminal, timers and child processes; a zero-grant handler runs once per event with a fresh budget; effects come from a closed table executed under the run's grants (#117). | `docs/reference/terminal_app.md` |
| `process:exec_inherit_env=` | A runner-only grant that passes the runner's environment to one absolute program. Child VMs cannot request it. `process:env=` still refuses `PATH`, `HOME` and the other code-loading names (#116). | `docs/reference/process_authority.md` |
| `--max-exec-millis`, `--max-processes` | A per-call exec time bound and a limit on exec children alive at once in the run (#114, #115). | `docs/cli.md` |
| `--max-event-instructions`, `--max-event-memory-bytes`, `--max-state-bytes` | Per-event limits for `terminal_app`. | `docs/cli.md` |
| `--replay` | Test a `terminal_app` deterministically from a recorded event file: one record per handled event, effects recorded and never executed, no grants needed (#118). | `docs/reference/terminal_app.md` |
| Separate child streams | `process_exit` carries stdout and stderr separately; `exec` keeps the combined stream (#113). | `docs/reference/terminal_app.md` |

## Behavior changes
- **Runtime error JSON.** On stderr and in `try_let` bindings it now starts with `"schema":"howlframe.runtime_error/v1"` (#112). Parsers that read fields are unaffected; code that compared the whole string must allow the new field.
- **Exec process limit.** At most 32 exec children may be alive at once by default (`--max-processes`). A program that legitimately runs more must raise the limit.
- **Signals to exec children.** The exec supervisor now catches SIGINT, SIGTERM and SIGHUP and forwards them to the child's process group. Ordinary `exec` is unaffected.
- **v0.2.1 fixes.** The `spawn` and input-bound changes from v0.2.1 apply here too; see `docs/releases/v0.2.1.md` on its tag.

## Compatibility
| | v0.2.x | v0.3.0 |
|---|---|---|
| `howlframe version` | `HowlFrame 0.2.x`, `HFBC format: 2` | `HowlFrame 0.3.0`, `HFBC format: 2` |
| Artifacts | format 2 | format 2. v0.2.x artifacts run on v0.3.0. An artifact using `TERMINAL_APP` needs v0.3.0. |
| Grants | | additive: `process:exec_inherit_env=` |

`terminal_app` runs on the bytecode VM only. The interpreter, HFIR and the Go, JavaScript and WebAssembly targets do not support it.

## Installation
Archives are named `howlframe_v0.3.0_<os>_<arch>.tar.gz` (`.zip` for Windows). Verify them against `SHA256SUMS`; the steps are those of `docs/installation.md` with `VERSION=v0.3.0`. Platform execution status there was recorded for v0.2.0 and is not re-claimed here.
