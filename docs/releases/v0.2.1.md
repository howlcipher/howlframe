# HowlFrame v0.2.1

## What it is
A patch release of v0.2.0. It is the `v0.2.0` tag plus four VM fixes, so
everything v0.2.0 documents (language, grants, artifact format 2,
compatibility) still applies. Later work on `main` is not included.

## Fixes
All four were found by HowlPlane's TUI-00 feasibility gate, which reproduced
each on v0.2.0's code line; consumer evidence and reproducers are recorded on
`main` in `docs/journals/2026-11-23_vm_spawn_and_input_bounds.md` and
howlcipher/howlplane `integrations/howlframe/tui00/reproducers/`.

| | Before | v0.2.1 |
|---|---|---|
| `spawn` instruction budget | each body had a whole `--max-instructions` of its own | one counter bounds the whole spawn tree |
| `spawn` nesting | unbounded | limited by `--max-call-depth`, like `spawn_agent` |
| Body and parent write one dict | Go `fatal error: concurrent map writes`, no structured error, no receipt | each body works on its own copy |
| `read_line` | a line of any size was buffered uncharged | charged as read; `LIMIT_EXCEEDED` at `READ_LINE` |
| `parse_json` | decoded value uncharged | charged; `LIMIT_EXCEEDED` at `PARSE_JSON` |

## Behavior change
A `spawn` body now receives a snapshot of captured dicts; its writes no longer
reach the spawner. Without a join they could only ever be observed racily.
See `docs/reference/process_authority.md`.

## Compatibility
| | v0.2.0 | v0.2.1 |
|---|---|---|
| `howlframe version` | `HowlFrame 0.2.0`, `HFBC format: 2` | `HowlFrame 0.2.1`, `HFBC format: 2` |
| Artifacts | format 2 | unchanged; v0.2.0 artifacts run on v0.2.1 and the reverse |
| Grants | | unchanged |

A program that relied on one run doing more than `--max-instructions` of
work across `spawn` bodies, or on reading more than `--max-memory-bytes` through
`read_line` or `parse_json`, now fails closed with `LIMIT_EXCEEDED`; raise the
runner's limit if the work is intended.

## Installation
Archives are named `howlframe_v0.2.1_<os>_<arch>.tar.gz` (`.zip` for Windows).
Verify them against `SHA256SUMS`; the steps are those of `docs/installation.md`
with `VERSION=v0.2.1`. Platform execution status there was recorded for v0.2.0
and is not re-claimed here.
