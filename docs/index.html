Overview

HowlFrame is an AI-native programming language and verified execution platform for adaptive software, designed so probabilistic reasoning can operate inside explicit deterministic boundaries.

Intent is not authority. Adaptive intelligence can reason and propose. Deterministic machinery controls permissions, capabilities, state, mutation, invariants, verification, and approval.

Generated Go remains the broadest backend. HowlFrame also includes JavaScript generation, WebAssembly Text targets, direct AST execution for a bounded CLI subset, and binary bytecode execution through the HowlFrame VM. The project is experimental, and each target rejects unsupported behavior rather than presenting roadmap work as complete.

Toolchain

  • Front end: lexer, parser, AST transforms, semantic checking, and an enforced HowlFrame Intermediate Representation (HFIR) verification gate.
  • Go target: cli_app and http_server programs emit server.go plus optional Go tests.
  • JavaScript target: web_app programs emit app.js plus optional Node tests.
  • WAT target: wasm_app emits structurally validated WebAssembly Text for the supported typed expression subset.
  • Standalone WAT target: -compile-wasm lowers a checked cli_app program through a typed SSA/CFG into WebAssembly Text with zero Go process at runtime — arithmetic, comparisons, if/phi control flow, structured while loops, and calls between defuns (including recursion) over scalar int/float/bool values, verified standalone with wasmtime.
  • Direct execution: -run interprets supported cli_app programs without writing generated source.
  • Bytecode: -compile-bc writes binary bytecode and -run-bc executes it in the VM, including native in-memory stores for structured records.

Why HowlFrame?

  • Uniform syntax: balanced S-expressions are easier to grammar-constrain than full-size languages.
  • Semantic feedback: invalid programs return localized JSON errors before backend output is written.
  • Explicit capabilities: behavior must have an implemented AST, IR, backend, or VM mapping.
  • Target-aware limits: unsupported backend and VM combinations are rejected rather than presented as universally available.

Quick Start

HowlFrame requires Go 1.21 or newer for normal toolchain use. Python, Outlines, OpenAI-compatible client support, and Ollama are optional for the local orchestrator experiment.

git clone https://github.com/howlcipher/howlframe.git
cd howlframe
go run howlframe.go examples/cli_hello.howl
go run server.go

Examples

CLI

(cli_app
  (print "Hello, World!")
  (let (name "HowlFrame")
    (print "Welcome to" name)
  )
)

HTTP

(http_server 8080
  (route "/" (lambda (req)
    (res 200 "text/plain" "Hello from HowlFrame")
  ))
)

Web App Logic

(web_app
  (defun increment (n)
    (type_hint n "int")
    (type_hint return "int")
    (return (+ n 1))
  )
)

Direct Execution

go run howlframe.go -run examples/cli_hello.howl

Bytecode

go run howlframe.go -compile-bc examples/cli_hello.howl
go run howlframe.go -run-bc examples/cli_hello.howl.bc.bin
go run howlframe.go -compile-bc tests/test_store_bytecode.howl -o /tmp/test_store_bytecode.hfbc
go run howlframe.go -run-bc /tmp/test_store_bytecode.hfbc
go run howlframe.go -run-bc --max-instructions 1000000 /tmp/test_store_bytecode.hfbc

Bytecode execution defaults to 100,000 instructions. Only the trusted runner may select another positive, finite ceiling; invalid values fail before execution, there is no unlimited sentinel, and instruction budgets never grant capabilities.

WebAssembly Text

go run howlframe.go -compile-wasm examples/native_math.howl -o /tmp/native_math.wat

Language Surface

  • Control flow: let, set, if, while, for, match, and do.
  • Functions and types: defun, call, return, type_hint, type_param, struct, parse_json, and schema_bridge for typed constrained-output boundaries in provider-neutral mask plans.
  • Collections and strings: lists, dictionaries, mutation, random-access reads, splitting, joining, regex matching, and deterministic conversions.
  • Runtime primitives: file I/O, subprocess execution, CLI args, HTTP fetches, middleware, environment reads, imports, includes, spawning, bytecode-native record stores, and native tests where supported by the target.
  • AI-oriented primitives: LLM generation, fuzzy casting, semantic assertions, semantic routing, neural circuits, ephemeral circuits, goal-driven execution, lazy synthesis, patching, context threading, runtime optimization blocks, compile-time optimization signatures, and agent tasks.

(optimize_signature name (metric "accuracy") (test "go test ./...") (candidate "baseline" "prompt") body) records compile-time optimization intent while evaluating body normally. Run go run howlframe.go -optimization-plan program.howl to print deterministic howlframe.optimization_plan/v1 JSON. Constrained decoding uses howlframe.mask_plan/v1. Plan generation never runs tests, calls a model, rewrites source, or selects a candidate.
