Zero

Overview

Zero is an AI-first, S-expression programming language and toolchain. It keeps source syntax small and uniform so language models can generate programs that are easier to constrain, check, and route to different execution paths.

Generated Go remains the broadest backend, but Zero now also includes JavaScript generation, a WebAssembly Text prototype, direct AST execution for a bounded CLI subset, and binary bytecode execution through the VM.

Toolchain

  • Front end: lexer, parser, AST transforms, semantic checking, and shared IR lowering.
  • Go target: cli_app and http_server programs emit server.go plus optional Go tests.
  • JavaScript target: web_app programs emit app.js plus optional Node tests.
  • WAT target: wasm_app emits structurally validated WebAssembly Text for the supported typed expression subset.
  • Direct execution: -run interprets supported cli_app programs without writing generated source.
  • Bytecode: -compile-bc writes binary bytecode and -run-bc executes it in the VM, including native in-memory stores for structured records.

Why Zero?

  • Uniform syntax: balanced S-expressions are easier to grammar-constrain than full-size languages.
  • Semantic feedback: invalid programs return localized JSON errors before backend output is written.
  • Explicit capabilities: behavior must have an implemented AST, IR, backend, or VM mapping.
  • Target-aware limits: unsupported backend and VM combinations are rejected rather than presented as universally available.

Quick Start

Zero requires Go 1.21 or newer for normal toolchain use. Python, Outlines, OpenAI-compatible client support, and Ollama are optional for the local orchestrator experiment.

git clone https://github.com/howlcipher/zero.git
cd zero
go run zero.go examples/cli_hello.zero
go run server.go

Examples

CLI

(cli_app
  (print "Hello, World!")
  (let (name "Zero")
    (print "Welcome to" name)
  )
)

HTTP

(http_server 8080
  (route "/" (lambda (req)
    (res 200 "text/plain" "Hello from Zero")
  ))
)

Web App Logic

(web_app
  (defun increment (n)
    (type_hint n "int")
    (type_hint return "int")
    (return (+ n 1))
  )
)

Direct Execution

go run zero.go -run examples/cli_hello.zero

Bytecode

go run zero.go -compile-bc examples/cli_hello.zero
go run zero.go -run-bc examples/cli_hello.zero.bc.bin
go run zero.go -compile-bc tests/test_store_bytecode.zero -o /tmp/test_store_bytecode.zbc
go run zero.go -run-bc /tmp/test_store_bytecode.zbc

WebAssembly Text

go run zero.go -o build examples/wasm_math.zero

Language Surface

  • Control flow: let, set, if, while, for, match, and do.
  • Functions and types: defun, call, return, type_hint, type_param, struct, parse_json, and schema_bridge for typed constrained-output boundaries in provider-neutral mask plans.
  • Collections and strings: lists, dictionaries, mutation, random-access reads, splitting, joining, regex matching, and deterministic conversions.
  • Runtime primitives: file I/O, subprocess execution, CLI args, HTTP fetches, middleware, environment reads, imports, includes, spawning, bytecode-native record stores, and native tests where supported by the target.
  • AI-oriented primitives: LLM generation, fuzzy casting, semantic assertions, semantic routing, neural circuits, ephemeral circuits, goal-driven execution, lazy synthesis, patching, context threading, optimization blocks, and agent tasks.
