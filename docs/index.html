SECTION // 01 System Overview

HF-MOD-OVERVIEW

LLMs excel at producing structural code proposals, but frequently struggle with syntax nuances, invalid API signatures, and cascading refactor drift. HowlFrame restricts source grammar to small, uniform, balanced S-expressions so generation can be grammar-constrained, type-checked, and validated before runtime.

Generated Go remains the broadest backend. HowlFrame also includes native JavaScript generation, WebAssembly Text (WAT) compilation, direct AST interpretation for bounded CLI tasks, and binary bytecode execution through the HowlFrame VM. Every target rejects unsupported constructs rather than pretending roadmap features are ready.

Concern Domain Adaptive Subsystem Deterministic Subsystem Boundary Guarantee
Reasoning & Generation Synthesizes logic, formulates plans, suggests transforms Rejects invalid grammar, enforces JSON schemas PROPOSAL ONLY
Intermediate Representation Emits candidate AST nodes HFIR typing, semantic validation, structural invariants VERIFIED
Capability Grants Requests permissions (net, db, fs) Runner strictly grants or denies capability tokens FAIL CLOSED
Runtime Execution None (isolated from execution) Bytecode VM, Go binary, JS app, or WAT compiler BOUNDED RUN

SECTION // 03 Compiler Toolchain

HF-MOD-TARGETS
  • Front End: Lexer, recursive-descent parser, AST transforms, semantic checking, and an enforced HowlFrame Intermediate Representation (HFIR) verification gate.
  • Go Target: cli_app and http_server programs emit server.go plus optional Go test suites.
  • JavaScript Target: web_app programs emit app.js with reactive DOM event bindings, asynchronous fetch, and optional Node tests.
  • WebAssembly Text (WAT) Target: -compile-wasm lowers checked cli_app programs through a typed SSA/CFG into WebAssembly Text with zero Go process at runtime — arithmetic, comparisons, if/phi control flow, structured while loops, and recursion over scalar values, verified standalone with wasmtime.
  • Direct Execution: -run interprets supported cli_app programs directly without emitting intermediate Go code.
  • Bytecode VM: -compile-bc emits binary bytecode (HFBC v1) and -run-bc executes it inside the VM, with runner-granted capability tokens and native record stores for structured persistence.

SECTION // 04 Why HowlFrame?

HF-MOD-RATIONALE

Uniform S-Expression Syntax

Balanced parentheses provide a deterministic grammar structure that LLMs can generate with strict token masking without syntax hallucinations.

Localized Semantic Feedback

Invalid programs return structured JSON diagnostic errors pinpointing exact line and AST coordinate mismatches before any backend generation occurs.

Explicit Runner Capabilities

Operations requesting network, database, or filesystem access must possess explicit tokens granted by the invoking host runner.

Target-Aware Boundaries

Features not supported by a backend target (e.g. DOM operations on WASM) fail cleanly at compile-time rather than crashing at runtime.

SECTION // 05 Quick Start & Toolchain Usage

HF-MOD-CLI

HowlFrame requires Go 1.21 or newer for normal toolchain compilation and runtime execution.

[TERMINAL // BUILD_AND_RUN] 
# 1. Clone repository
git clone https://github.com/howlcipher/howlframe.git
cd howlframe

# 2. Compile and run CLI example
go run howlframe.go examples/cli_hello.howl
go run server.go

# 3. Compile to Bytecode and execute in VM with finite budget
go run howlframe.go -compile-bc examples/cli_hello.howl -o build/hello.hfbc
go run howlframe.go -run-bc --max-instructions 100000 build/hello.hfbc

# 4. Compile directly to WebAssembly Text (WAT)
go run howlframe.go -compile-wasm examples/native_math.howl -o build/math.wat

Bytecode execution defaults to 100,000 instructions. Only the trusted runner may specify a different positive, finite ceiling; invalid values fail closed before execution.

SECTION // 07 Language Surface & Primitives

HF-MOD-PRIMITIVES
  • Control Flow: let, set, if, while, for, match, try_let, and do.
  • Functions & Types: defun, call, return, type_hint, type_param, struct, parse_json, and schema_bridge for typed constrained-output boundaries.
  • Collections & Strings: Lists, dictionaries, random-access mutations, splitting, joining, regex matching, and deterministic type conversions.
  • Runtime Primitives: File I/O, subprocess execution, CLI argument parsing, HTTP clients, CORS headers, environment variables, imports, and bytecode-native persistent record stores.
  • AI-Oriented Primitives: LLM generation, fuzzy casting, semantic assertions, semantic routing, neural circuits, ephemeral circuits, goal-driven execution, lazy synthesis, runtime optimization blocks, and agent tasks.
