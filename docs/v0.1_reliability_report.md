# HowlFrame v0.1 Reliability Report

## Overview
HowlFrame has reached its v0.1 release-candidate baseline. This milestone establishes an experimental capability-bounded standalone bytecode runtime with deterministic execution policy and tested fail-closed boundaries.

## Artifact envelope
**TESTED**
Bytecode compilation produces a binary envelope (`.hfbc`) containing:
- Magic bytes (`HFBC`) to prevent misinterpreting arbitrary files.
- A format version integer.
- A 32-byte SHA-256 checksum.
- A gob-encoded payload containing the bytecode instructions.

## Artifact size limit
**TESTED**
The runtime establishes a trusted upper bound for artifact payloads to prevent untrusted artifact headers from commanding large memory allocations. The maximum payload size is capped at 10 MiB (`MaxArtifactPayloadSize`), preventing OOM attacks from malformed or maliciously large length fields.

## Integrity vs authenticity
**KNOWN LIMITATION**
The 32-byte SHA-256 checksum provides structural integrity verification to detect truncation and accidental corruption. It does NOT prove artifact authenticity, trustworthiness, or origin, as an attacker modifying an artifact could simply recompute the checksum. Cryptographic signing is not implemented in v0.1.

## Bytecode structural validation
**TESTED**
The runtime includes a structural verifier that runs after the gob payload is decoded and before execution begins. The verifier ensures the program cannot violate VM assumptions, explicitly rejecting:
- Unknown opcodes
- Out-of-bounds jump targets
- References to missing functions

## Reproducible-build result
**KNOWN LIMITATION**
Due to Go's non-deterministic map iteration order being preserved during `gob` serialization of the `Functions` dictionary, repeated compilation of the exact same source code into `.hfbc` produces slightly varying artifact bytes. Byte-deterministic outputs are not claimed in v0.1.

## Capability enforcement
**PROVEN**
Capabilities (`Network`, `Filesystem`, `Process`, `Environment`, `Database`) are enforced strictly at the VM level. An artifact attempting an operation without the corresponding `-allow-caps` CLI flag deterministically panics with `CAPABILITY_DENIED` prior to execution. Capability authorization is fully isolated from untrusted payloads and cannot be elevated from within the artifact.

## Instruction budgets
**PROVEN**
The runtime maintains a strict instruction execution budget (default 100,000 instructions) controlled solely by the trusted runner. Infinite loops and other excessive execution patterns exhaust the budget and panic deterministically (`LIMIT_EXCEEDED`). Zero or negative limits fail immediately.

## Bug #42 result
**PROVEN**
Legitimate unbound references fail to build at the semantic checker level prior to intermediate representation verification, while dynamic runtime lookups (e.g., `try_let`, parsed JSON elements, dictionary access) succeed safely.

## Coverage matrix methodology
**PROVEN**
The construct coverage matrix (`docs/reference/construct_coverage.md`) is now generated strictly from authoritative metadata found in `internal/construct` and `internal/capability`. Heuristic matching and derived assertions have been removed.

## Malformed input results
**TESTED**
The bytecode parser and structural verifier fail closed when exposed to malformed or adversarial inputs. Empty files, short magic bytes, wrong magic bytes, unsupported versions, oversized payload claims, truncated payloads, missing checksums, trailing garbage, valid envelopes with invalid payloads, and known opcodes with invalid jump targets all deterministically result in rejected execution.

## Known security limitations
**NOT CLAIMED**
HowlFrame does NOT provide or guarantee OS-level sandbox isolation, container isolation, memory-safe execution, formal verification, or production-grade protection against novel VM escapes.

## Flagship application results
**TESTED**
Flagship applications—Todo CLI, Task API, Release Authority, Bounded Action Executor, and Repo Analyst—successfully compile from `.howl` source to standalone `.hfbc` artifacts and execute as expected via the HowlFrame VM, completely isolated from their source files.
