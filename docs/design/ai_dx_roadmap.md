## AI-DX1: Understanding

First deliverable: proposed `agent capabilities`, `agent describe`, `agent check --json`, and `agent explain` interfaces. Define a versioned deterministic schema before implementation: target, construct signatures, actual runner grants, limitations, stable diagnostic codes and locations, and executable example references. Sort output deterministically; distinguish unsupported from unknown and unavailable evidence. Never infer authorization from construct availability.

Extend `internal/construct/`, `internal/hfir/diagnostic.go`, backend registries and existing diagnostic machinery. Reuse avoids a second language catalog, but metadata is fragmented and must be reconciled. A separate manually maintained capability database would be easier to prototype but risks drift and false support claims. The standalone bytecode registry must not imply JavaScript, Go or WasmGC support. Unknown coverage stays explicit.

Acceptance: registry/output consistency checks, explicit unknown-target rejection, stable diagnostic contracts and examples actually compiled/executed on each claimed target. Begin with a small verified target/construct slice; expand only with evidence.

## M6: Application trial

First deliverable: generate `src/editor/editor.css`, `src/site/site.css` and the editor shell from `.howl`, then enforce `.howl`-only maintained application source under `src/`.

Prefer a WasmGC generator emitting a small JSON asset manifest consumed by existing assembly and CSP tooling. Define a versioned manifest with an allowlisted asset name and text content; reject duplicate, absolute and traversal paths. Preserve loader ordering, CSP, provenance and artifact budgets. This uses current language features and existing build tooling, but retains string-based presentation authoring and escaping costs. A new HTML/CSS language offers structured validation and composition at substantially greater parser, type-system and tooling scope. Defer it until the trial demonstrates a measured need.

Acceptance: generated byte/DOM/CSP equivalence, source-policy rejection of maintained non-`.howl` files, provenance and browser behavior including accessibility, exports and motion. Follow the [M6 handoff](../journals/2026-11-04_wasmgc_m6_prompt.md); do not implement M6 in M5 closeout.

## AI-DX2: Session efficiency

First deliverable: proposed `agent snapshot`, task-scoped `agent context`, and `agent status --verified`, backed by a local versioned evidence manifest.

Record source hashes including relevant uncommitted and untracked inputs, compiler revision/binary hash, dependency lockfiles, configuration, command arguments, environment inputs, exit codes, test results and evidence hashes. Separate task claims from observed results. Write atomically; interrupted runs remain incomplete. Initially invalidate conservatively whenever any relevant input changes. Hash matching alone does not make an untrusted report authoritative; record producer and verification provenance.

A local manifest is inspectable and needs no service or database, but conservative invalidation repeats work and requires explicit input discovery. A database/service adds concurrent indexing and queries at the cost of operational and authority complexity. Defer it until measured need exists.

Acceptance: changed source/compiler/dependencies/configuration/test inputs invalidate results; missing or altered evidence fails closed; interrupted runs never appear successful; repeated session recovery preserves exact state and remaining actions.

## AI-DX3: Semantic repair

First deliverable: bounded repair reusing trusted regions, graph/node preconditions, protected hashes, atomic rejection and reverification. `internal/hfir/model_adapter.go` already supports up to five same-kind replacements. Preserve the production AST compilation path and HFIR verification gate.

Establish compact authenticated context and reliable source-region mapping first. Graph repair is not safe `.howl` source editing: line/column provenance does not establish lossless replacement boundaries, comments, whitespace or round trips. The [recorded localization gate](../journals/2026-08-13_hfir_localization_phase3c_decision_gate.md) reports complete repair requests of 5,162 B and 19,576 B against full graphs of 3,743 B and 16,486 B; measure complete context and patch costs, not delta bytes alone. Arbitrary restructuring and dependency insertion remain later work.

Reusing the bounded transaction machinery preserves existing invariants but limits repair expressiveness. General source rewriting offers flexibility with substantially larger mapping, formatting and authority risks. Do not widen the repair boundary merely to improve benchmark completion.

Acceptance: reject stale, unauthorized and out-of-region patches atomically; preserve protected regions; verify source round trips and affected behavioral contracts; recompile through the normal AST/HFIR path before claiming success.

## Preregistered measurement protocol

Before implementation, freeze matched tasks, starting revisions and dependency/tool versions. Use equal model and tool budgets, the same allowed tools and no-payment execution route, randomized matched ordering, and held-out checks that are not exposed during repairs. Include clean starts, invalid usage, maintenance changes and predefined interruptions immediately after edits, during verification and after evidence recording. Record unsuccessful and interrupted attempts rather than discarding them.

Measure each milestone separately against its immediate predecessor. Record input/output context, repair payload, snapshot creation/recovery, verification tokens and elapsed time, total wall time, command count, retries and correctness. Include manifest/evidence maintenance and invalidation overhead. Freeze success criteria and aggregation before runs; report per-task paired results, dispersion and failures, not only favorable averages. Keep application changes identical between matched conditions where possible and disclose unavoidable differences.

Experimental targets: 30% less AI-DX1 context, 50% less invalid usage, 50% less resume context, 30% fewer maintenance tokens and 20–25% less overall time. These are hypotheses, not acceptance evidence. Correctness and resumption reliability must not regress. Use deterministic fixtures now; defer live-agent comparisons until a verified no-payment route exists. No paid model calls, plan upgrades, larger runners or private hosted runs with unverified cost are authorized.
